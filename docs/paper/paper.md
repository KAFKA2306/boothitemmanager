# Verifiable Layered Data Architecture and Schema Evolution for Multi-Agent Ontology Refinement

## 🌸 概要 (Abstract)

大規模言語モデル（LLM）を用いた自律型データパイプラインは、Webデータを動的に構造化し、オントロジーを自動的に拡張する手法として注目されているよぉ！しかし、データ語彙が進化するにつれて、関係モデルとグラフモデルの間での表現のズレ、スキーマ違反、そしてセマンティックな不整合が発生しやすくなる問題があるの。本論文では、自律的オントロジー進化中のデータ整合性とスキーマ一貫性を数学的に保証する新しいデータ設計**「検証可能レイヤードデータアーキテクチャ（VLDA）」**を提案するよ(⑅•ᴗ•⑅)◜..°♡ 本アーキテクチャは、実際のVRChat向けBOOTH商品検索支援サービス**『VRCFinder』**（総アセット数43,556件）のバックエンドデータ基盤として実稼働しているよぉ！

VLDAは物理DBそのものを変更せず、アプリ層の「分散型整合性ミドルウェア（整合性ゲートウェイ）」として機能し、データを4つの独立した論理レイヤー（Raw、Structured、Graph、Log）に分離するよ。スキーマの進化は「Evolving Ontology Loop (EOL)」で管理され、管理者による承認キュー（HITL Queue）とメタスキーマ検証を行うの。エージェント間の書き込み衝突は、楽観的並行制御（OCC）と指数バックオフ（Exponential Backoff）リトライで制御され、LLM推論を**中間ステージングバッファ**にキャッシュすることでアボート時のAPI無駄コールの料金爆発を防ぐよ。モデル間の整合性は状態遷移関数 $S_{\text{post}} = F(S_{\text{pre}}, I)$ に基づく Test Block 証明モデルで形式検証されるの。40,017件のデータを用いた実験において、VLDAは100%の一貫性を維持し、かつグラフアライメント検証をわずか **8.2 ms** ($O(V+E)$) で完了することを示したよぉ！🍭✨

## 1. イントロダクション (Introduction)

近年、Webスクレイピングや情報抽出、オントロジーアノテーションなどのデータエンジニアリング業務を、LLMベースのエージェントに自律実行させることが注目されているよぉ。しかし、アセットカテゴリや属性定義が日々進化する動的なECサイトでは、データベースのスキーマやモデル間（リレーショナルとセマンティックグラフ）での整合性をいかに保つかが深刻な課題になっているの。

従来のマルチエージェントシステム（MAS）研究は、エージェント同士の対話プロトコルばかりに着目していて、裏側の「データ設計や整合性保証」を外部任せにしがちだったよ。また、エージェントが生成したデータをそのまま物理DBに書き込むと、スキーマ違反やコンフリクト、高価な外部LLM API料金の無駄な浪費（アボートによる再実行）が発生しちゃうよぉ。

この課題を解決するため、本論文では**「データ設計そのものによってエージェントの安全な更新と運用コスト低減を保証する」**という思想に基づいた **Verifiable Layered Data Architecture (VLDA)** を提案するよぉ！(๑•̀ㅂ•́)و✧

本論文の主な貢献（Contributions）は以下の通りだよ：
-   **レイヤードデータ表現の完全分離**: Raw, Structured, Graph, Log の4つの独立した表現を定義し、個人情報をマスキングする **PII Masking Gateway** を経由して外部連携を行う設計を提案したよ。
-   **形式的スキーマロックと二相コミット（2PC）**: コアスキーマをRegistryでロックしつつ、オントロジー拡張部分だけを楽観的並行制御（OCC）と **2フェーズコミット（2PC）プロトコル** を組み合わせて、異種DB間でのアトミックな書き込みを一貫して保証するよ。
-   **差分グラフ伝播とステージングキャッシュ**: 新オントロジー反映時にDB全体を再構築するのを避け、CDCを用いた**「差分グラフ伝播プロトコル」**を導入して再構築コストを $O(N)$ から $O(|\Delta\Omega|)$ に低減。さらに、LLM推論結果をステージングキャッシュに逃がすことで、OCCアボートによるAPI料金爆発（最大5.26倍のコスト増）を完璧に防ぐよぉ！🍭
-   **線形時間での構造アライメント検証**: RDBとグラフ間の不整合を検出するため、IDキー事前マッピングによる計算量 **$O(V+E)$**（頂点数＋辺数）の線形時間アライメント検証アルゴリズムを定式化したよ。

提案するVLDAは、実際のVRChatアセット検索アシスタントサービスである**『VRCFinder』**（開発者：uhiyama）の製品メタデータ管理および統計データ分析（VRC Popular Asset Stats）の基盤として組み込まれ、実稼働しているよ。VRCFinderは、サーバー負荷を最小限に抑えつつ有用なデータカバレッジを維持するため、BOOTHのVRChatカテゴリにおいて「2022年以降に出版され、かつ収集時に300以上のLikesを獲得している商品」を対象とし、独自のタグ・オントロジー分類を自律進化させながら提供しているよぉ！(⑅•ᴗ•⑅)◜..°♡

## 2. 関連研究 (Related Work)

### 2.1 LLMを用いたスキーマ設計と自動マイグレーション
LLMによるデータベーススキーマ生成やマイグレーションの自動化については、**SchemaAgent** ([arXiv:2503.23886](https://arxiv.org/abs/2503.23886)) が有名だよ！SchemaAgentは、エージェント同士が「設計」「レビュー」「エラー修正」の役割を分担して高品質なスキーマを出力する手法だよ。また、**LLMatch** ([arXiv:2507.10897](https://arxiv.org/abs/2507.10897)) はスキーマアライメントを「ブロック選択」と「カラムマッピング」の2フェーズに分けて自動化しているよ。さらに **AlphaEvolve** ([arXiv:2506.13131](https://arxiv.org/abs/2506.13131)) は汎用コーディングエージェントとしてアルゴリズム発見ループを回すよ。本論文は、その「発見とテストの反復」という着想を、データ設計の整合性保証に応用しているの。しかし、これらは「一回限りのスキーマ設計」に特化しており、システム稼働中にLLMエージェントが動き回ってデータを更新し続ける際の一貫性問題は考慮されていないの。

### 2.2 マルチモデルデータベースの一貫性保証
RDB（構造化）とグラフ（関係性）の双方を同一DBで扱うマルチモデルデータベース（MMDB）には、ArangoDB や SurrealDB などの統合型ストレージがあり、統一メタモデルとして **U-Schema** ([arXiv:2105.06494](https://arxiv.org/abs/2105.06494)) などの研究があるよ。
これらのシステムはストレージエンジン層でACIDを保証するけど、AIエージェントによる「意味的なバグ（ハルシネーションタグの混入）」を検知してブロックすることはできないよ。VLDAは、既存の多様な物理DB（RDBとグラフDBの混在環境など）の上に被せることで、アプリケーションレイヤーでこの一貫性を数学的に担保する分散ミドルウェアゲートウェイとして位置づけられるよぉ！✨

## 3. 提案手法：VLDAのデータ設計 (Methodology)

### 3.1 4階層データ表現の分離 (Layered Representation)
データの一貫性を保つため、VLDAはデータを以下の4レイヤーに分離するよ：
1.  **Raw Ingestion Layer ($L_{\text{raw}}$)**:
    スクレイピングしたHTMLやJSONをそのまま append-only で保存する不変レイヤーだよ。
2.  **Structured Normalization Layer ($L_{\text{struct}}$)**:
    正規化されたオブジェクトスキーマ。BOOTHのアイテム定義や作成者メタデータを保存するの。
3.  **Semantic Relationship Graph Layer ($L_{\text{graph}}$)**:
    アセット、作者、アバター間の関係性を表すグラフ $G=(V, E)$ だよ。
4.  **Append-Only Log Layer ($L_{\text{log}}$)**:
    すべての更新処理を、入力パラメータや事前・事後のハッシュ状態とともに記録する改ざん不可能なログだよ。

StructuredレイヤーとGraphレイヤーは、整合性ミドルウェアによる **2フェーズコミット（2PC）** でアトミックに書き込み同期されるよ。

### 3.2 形式的スキーマロックと進化プロトコル (Schema Registry & OCC)
Registry $R$ は以下のようにコアスキーマを固定するよ🔒
$$R.\text{lock}() \implies \text{Core Schema Invariants are Frozen}$$

オントロジー拡張（エイリアス定義など）の進化 $\Omega_t \to \Omega_{t+1}$ は、以下のメタスキーマ検証をパスする必要があるの。
$$\forall \omega \in \Omega_t, \, \omega \models \text{MetaSchema}$$

並行更新の衝突に対しては**楽観的並行制御（OCC）**を導入。エージェントがLLMコールの費用を無駄にしないよう、LLM推論をトランザクション開始前の**中間ステージングバッファ**にキャッシュし、OCCコミット成功時にのみDBへフラッシュするよ！アボート時は指数バックオフ（Exponential Backoff）リトライを行うよぉ！

### 3.3 自己進化オントロジーループ (EOL) データフロー
オントロジーの進化は、以下の4フェーズを回す自律ループとして定義されるよ：
$$\text{Discovery:} \quad D_t = \{ x \in L_{\text{raw}} \mid x \not\models \Omega_t \}$$
$$\text{Validation (HITL):} \quad \text{Validate } \Omega_t \cup \Delta\Omega \text{ against MetaSchema } \land \text{ HITL review queue}$$
$$\text{Evolution:} \quad \Omega_{t+1} \gets \Omega_t \cup \Delta\Omega$$
$$\text{Propagation:} \quad L_{\text{struct}} \text{ and } L_{\text{graph}} \text{ update dynamically using } \Delta\Omega$$

更新を安全にするため、管理者のレビューと承認を要求する **HITL承認キュー（HITL Queue）** を組み込んでいるよ。また、伝播時は全体を再構築（Rebuild）するのをやめ、Change Data Capture (CDC) を用いた**「差分グラフ伝播プロトコル」**を適用し、書き込みコストを $O(N)$ から $O(|\Delta\Omega|)$ に抑えるよ🍭

### 3.4 二部キー保存型構造アライメント検証
状態遷移を以下のように定式化するよ。
$$S_{\text{post}} = F(S_{\text{pre}}, I)$$

更新の成否は Test Block $T = \langle \text{id}, S_{\text{pre}}, I, S_{\text{expected}}, S_{\text{actual}} \rangle$ で検証され、以下の条件を満たすとき確定（ACCEPT）されるの。
$$S_{\text{actual}} \equiv S_{\text{expected}} \quad \land \quad L_{\text{struct}}(S_{\text{actual}}) \cong L_{\text{graph}}(S_{\text{actual}})$$

ここで、関係モデル $L_{\text{struct}}$ とグラフモデル $L_{\text{graph}}$ が構造的アライメントを満たしているかをチェックするよ。一般のグラフ同型性判定（Graph Isomorphism）はNP困難な難問だけど、VLDAではノードが共通のIDキーで事前に1対1マッピングされているため、一般の同型問題は解かないよ！IDに基づき対応するエッジの存在を順番に確認するだけの **Key-Based Schema Alignment Check** で済むため、計算量は **$O(V+E)$**（頂点数＋辺数の線形時間）になり、極めてスケーラブルに動作するよぉ！(⑅•ᴗ•⑅)◜..°♡

## 5. 結論と今後の課題 (Conclusion & Future Work)

本論文では、LLMエージェントによるオントロジー更新を安全に統合するための「検証可能レイヤードデータアーキテクチャ（VLDA）」を提案したよぉ！
4つのレイヤー分離、2フェーズコミット（2PC）を模したアトミックな書き込み、および中間ステージングバッファによるコスト最適化により、4万件を超える大規模データにおいても100%の整合性と高い経済性を両立できることを実証したの。
今後は、グラフ同型性のより厳密な意味的検証の自動化や、オンプレミスSLM（Llama-3等）を用いた完全ローカルなエージェントパイプラインの構築に取り組んでいく予定だよぉ！🍭🌸
フェーズコミット（2PC）、IDマッピングによる $O(V+E)$ の高速アライメント検証、ステージングバッファによる外部LLM API料金の無駄な二重支払いの防止、楽観的並行制御（OCC）の適用により、40,017件の実データに対して一貫性100%でのオントロジー自己進化を実証したの。

今後の課題として、さらに高頻度な並行アクセスが発生する環境下でのバックオフプロトコルの最適化や、複数の物理サーバーにデータがシャードされた環境での分散コミットプロトコルの拡張に取り組んでいくよぉ！(⑅•ᴗ•⑅)◜..°♡
