# 💖 BoothItemManager2 技術評価メトリクス仕様書だょ！ (⑅•ᴗ•⑅) 💖

このドキュメントは、BoothItemManager2のパフォーマンス、データ整合性、および処理の正確性を厳密かつ可愛く測定・評価するための技術仕様書だよぉ！
信頼できるシステムづくりのために、eval-harness原則（再現性・決定性・統計的有意性）をベースに設計したよ☆

## ⚡ 1. 検索性能メトリクス (Search Performance Metrics)

メモリ上での検索やクエリ実行のスピードが遅くてユーザーが「しゅん(´・ω・`)」としないように、厳しく測定するよ！

### 📊 測定ターゲットと許容値
| 評価項目 | 測定シナリオ (データ件数 $N$) | 許容値 (p50) | 許容値 (p95) | 限界値 (p99) |
| :--- | :--- | :--- | :--- | :--- |
| **単一キー検索** | $N = 10,000$ (インデックス検索) | $\le 1.0\text{ ms}$ | $\le 3.0\text{ ms}$ | $\le 5.0\text{ ms}$ |
| **複数条件フィルタ** | $N = 10,000$ (カテゴリ + タグ) | $\le 2.0\text{ ms}$ | $\le 5.0\text{ ms}$ | $\le 8.0\text{ ms}$ |
| **あいまいテキスト検索**| $N = 10,000$ (類似度検索) | $\le 5.0\text{ ms}$ | $\le 12.0\text{ ms}$ | $\le 20.0\text{ ms}$ |
| **大規模スケール負荷** | $N = 100,000$ (全条件混合) | $\le 15.0\text{ ms}$ | $\le 35.0\text{ ms}$ | $\le 50.0\text{ ms}$ |

### 🛠️ 評価方法
*   **コールド/ホットの分離**: OSキャッシュやPythonランタイムのメモリに乗っていない状態（コールド起動）と、キャッシュが効いている状態（ウォームアップ完了後）のそれぞれで100回試行して別々に集計するよ！
*   **クエリミックス検証**: 単純なIDマッチングだけでなく、実ユーザーがよく使う「VRChat向け衣装 ＋ 特定の対応アバター ＋ 最新登録順」といった複雑な絞り込みを再現したテストスイートで計測するよっ。

## 🌀 2. インデックスマージ＆永続化メトリクス (Index Merge Performance)

新しいアセット情報が追加されたときの、インデックスの差分マージとディスクへのアトミック書き込み性能だよ！

### 📊 測定ターゲットと許容値
*   **インデックス更新時間 (Segment Merge Time)**: 
    *   追加レコード $M = 100$ 件時のインデックス再構築・統合処理： $\le 50\text{ ms}$ (目標値) / $\le 100\text{ ms}$ (限界閾値)
*   **最大メモリ使用率スパイク (Peak RAM Overhead)**:
    *   マージ処理中に割り当てられる一時メモリ量： 既存インデックスサイズの **1.5倍以内** に抑えること☆
*   **アトミック書き込み安全性 (Atomic Write Robustness)**:
    *   書き込み中の異常終了時（強制終了シグナル等）のデータ破損率： **0.0%** (テンポラリファイルへの書き出し ➔ `os.replace` によるアトミック置換を義務化するよ！)

### 🛠️ 評価方法
*   マージ前後のファイルハッシュ確認によるデータ完全性検証。
*   複数プロセスによる同時書き込み競合（ロック待機時間および競合エラー率）の測定。

## 💾 3. キャッシュロード性能メトリクス (Cache Load Time)

お気に入り数（Likes）などの外部キャッシュデータをシステム起動時にロードする時の負荷と速度だよ！

### 📊 測定ターゲットと許容値
*   **初期キャッシュロード時間**:
    *   データ件数 $N = 10,000$ 件のキャッシュ（`likes_cache.json`）： $\le 10.0\text{ ms}$ (目標値) / $\le 30.0\text{ ms}$ (限界閾値)
*   **メモリフットプリント**:
    *   キャッシュエントリ1件あたりのメモリ使用量： $\le 200\text{ bytes}$
*   **キャッシュミス時のペナルティ低減率**:
    *   キャッシュミスの際、直ちに全体をロックせず、非同期バックグラウンドでHTMLスクレイピングを行うまでのキュー遅延： $\le 5.0\text{ ms}$

### 🛠️ 評価方法
*   キャッシュデータサイズをダミーで拡張（1MB, 10MB, 100MB）したときの読み込み時間とメインスレッドのブロッキング時間を計測するよ！

## 🎯 4. ノーマライザ変換精度メトリクス (Normalizer Correctness)

カオスなHTMLからきれいにメタデータやカテゴリを抽出できるか、そのお利口度を測定するよ！

### 📊 測定ターゲットと許容値
*   **カテゴリ・対応アバター判定精度 (VRChat Target Extraction F1-Score)**:
    *   アバター衣装、アセット、ワールド用等の分類適合率・再現率： **F1-Score $\ge 0.98$** (誤分類は即REJECT基準だよ！)
*   **PIIマスキング漏れ率 (PII Masking Leakage Rate)**:
    *   DiscordのID、Shopの固有ID、生URL等の隠蔽漏れ件数： **0件** (完全一致チェック)
*   **HTML変更耐性 (Layout Drift Robustness)**:
    *   BOOTHのHTMLレイアウトが一部変更（クラス名やタグ構造の微小変化）された場合のパース成功率： **$\ge 95\%$** (フォールバックパースの正常稼働)

### 🛠️ 評価方法
*   **ゴールデンデータセットによる差分テスト**: 人間が手動でラベル付けした「正解HTMLセット（100件以上）」とノーマライザの出力を厳密に比較するよ☆

## 🛡️ 5. テストハーネス (Eval-Harness) 原則

すべての評価を正しく公平に行うための大事なお約束ごとだよぉ！

1.  **環境の隔離 (Sandboxing)**: 
    *   評価用データベースとインデックスは、テスト実行ごとに初期化され、ホストマシンのファイルキャッシュに依存しない状態で測定すること。
2.  **決定性の確保 (Determinism)**:
    *   同一テストケース、同一ハードウェアリソースの下では、速度のブレが $\pm 5\%$ 以内に収まるようにダミー負荷を排除すること。
3.  **カオスインジェクションの常時実行 (Chaos Testing)**:
    *   評価時に「壊れたJSON」「不正なエンコーディングのHTML」「データベース接続の瞬断」を注入し、システムがクラッシュせずに正しいエラーTest Blockを生成できるか検証すること。
