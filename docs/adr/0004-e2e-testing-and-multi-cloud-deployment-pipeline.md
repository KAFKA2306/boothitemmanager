# ADR 0004: E2Eテスト導入とマルチクラウド・デプロイ・パイプラインの確立 🌸

## ステータス (Status)
**承認済み (Accepted)** ✨

## 背景 (Context) 🎀
BOOTHアセットが4万件を超える巨大な静的SPA（Single Page Application）において、以下の「かなしい」問題が発生していました。
- デプロイ時に必要なJSONファイル（APIデータ）が不足し、`DATABASE OFFLINE` エラーでアーカイブが壊れることがありました 😿
- フロントエンドの初期化（Splash画面）で停止してしまうバグを事前に検知する仕組みがありませんでした。
- Cloudflare Pagesの自動検知機能が、私たちの「脂肪ゼロ（Zero-Fat）」な構成を正しく理解できず、HugoやWorkerと勘違いしてビルドに失敗していました。

## 決定事項 (Decisions) 🍭
1. **PlaywrightによるE2Eテストの強制導入:**
   - `tests/e2e/test_browser.py` を作成し、スモークテスト、データ整合性、フィルタ動作、モーダル表示を自動検証するようにしました。
   - GitHub Actions上で、テストに合格した「えらい」ビルドだけがデプロイされる「鉄の掟」を確立しました 🦾
2. **`build_static.sh` による「梱包」の統一:**
   - GitHub PagesもCloudflare Pagesも、同じこのスクリプトを使って `dist/` ディレクトリを構成するようにしました。これで「どこでもいっしょ」な動作を保証します。
3. **データスキーマの柔軟な受け入れ:**
   - 昔の形式（`id`, `author`）と新しい形式（`item_id`, `creator_name`）の両方をフロントエンドで優しく受け入れるようにしました。これでリンク切れがなくなりました！🔗
4. **スタイル選択のシングル化:**
   - 「VISUAL STYLE」は1つだけ選ぶのが一番使いやすいので、シングルセレクトに変更しました 👗

## 帰結 (Consequences) 🌟
- **安心・安全！:** テストが通らないとデプロイされないので、アーカイブが壊れたまま公開される心配がなくなりました。
- **マルチクラウド対応:** GitHub PagesとCloudflare Pagesの両方で、全く同じ品質のサイトが配信されます。
- **デバッグが楽ちん:** もし壊れても、スプラッシュ画面に赤い文字でエラーが出るので、すぐに原因がわかります 🚩

---
この決定により、BoothItemManager2は「絶対に壊れない最強のアーカイブ」へ一歩近づきました！やったね！✨🍡
