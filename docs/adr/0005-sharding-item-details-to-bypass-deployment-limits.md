# ADR 0005: シャーディングによるデプロイ制限の回避とデータ構造の最適化 💎



## 背景 (Context) 🎀
BoothItemManager2は、4万件を超えるアイテムの「きめ細やかな」詳細情報を保持しています。
これまでは1アイテムにつき1つのJSONファイル（計40,000ファイル以上！）を作成していましたが、以下の「こまった」問題に直面しました。
- **Cloudflare Pagesの壁:** 無料プランではファイル数が20,000個までに制限されており、デプロイが拒否されてしまいました 😿


## 決定事項 (Decisions) 🍭
「Zero-Fat（脂肪ゼロ）」かつ「High-Performance」なアーカイブを目指し、以下の「大改造」を行いました。
1. **アイテム詳細のシャーディング (Sharding):**
   - 40,000個のファイルをそのままにするのではなく、アイテムIDの下2桁などを元に **100個の「シャード（断片）ファイル」** (`api/details/shard_00.json`〜`shard_99.json`) に集約しました。
   - これにより、ファイル数は **40,000個 → 100個** へと、なんと **99.7%も削減** されました！🚀
2. **フロントエンドの動的取得ロジック:**
   - `index.html` の詳細表示（モーダル）を開く際、アイテムIDから瞬時に「どのシャードに入っているか」を計算し、必要なシャードだけを `fetch` する仕組みにしました。
