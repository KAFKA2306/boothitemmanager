# ADR-0003: Zero-Fat Data Consolidation (冗長データの粛清)

## 📅 日付
2026-06-11

## 🚦 ステータス
承認済み (ACCEPTED)

## 📝 コンテキスト（背景だよぉ！）
「動けばいい」という考えで機能を追加し続けた結果、システムの中に「脂肪（無駄なデータ）」が溜まってきちゃったんだよぉ。
1.  **ストレージの無駄**: `api/catalog.json` と `data/structured/catalog.json` で同じ内容が 40MB 以上も重複していたよ。
2.  **API の肥大化**: フロントエンドでは part1/part2 に分けてロードしているのに、20MB もあるフルセットの `catalog_summary.json` を生成し続けていたの。
3.  **真実の分散**: 複数のファイルに同じ情報が書き込まれるせいで、「どれが最新のデータなの？」って迷子になりやすかったんだよ🍭

## 💡 決定事項（こうしたよぉ！✨）

### 1. 冗長 JSON ファイルの物理的粛清
リポジトリから約 70MB 以上の「脂肪」を削ぎ落としたよ！
-   **`api/catalog.json` 削除**: 内部ストレージ用の `data/` 側を唯一の真実（Source of Truth）として一本化。
-   **`api/catalog_summary.json` 削除**: 分割済みの JSON（part1/part2）だけでランタイムは十分だよ🍭
-   **孤立データの排除**: 中身が空だった `catalog_summary_filtered.json` や、重複していた `items/all.json` をすべて削除したよ。

### 2. Builder ロジックの筋肉質化
コードの中にある「二重書き込み」のボイラープレートを徹底排除したよ！
-   **Single Path Write**: `db_builder.py` や `api_generator.py` をリファクタリングして、一つのファイルにだけ魂を込めて書き込むようにしたの✨
-   **Tag Graph の参照最適化**: `tag_graph_builder.py` のソースを API 用の残骸から、構造化されたマスターデータに繋ぎ変えたよ。

## 🌈 得られた結果（どうなったかな？）
-   **爆速デプロイ**: リポジトリのサイズが劇的に小さくなって、GitHub への Push がとっても軽くなったよぉ！🚀
-   **メンテナンス性の向上**: 「このファイルを直したらあっちも直さなきゃ…」という心配がなくなって、変更が 1 箇所で完結するようになったよ✨
-   **純粋なランタイム**: `api/` ディレクトリには、クライアントが必要とする最小限の、磨き抜かれたデータだけが残るようになったんだよぉ！(๑•̀ㅂ•́)و✧

---
**この決定は、Zero-Fat の公理に基づき、不要スクリプトの削除と、35.55 秒で完走するスリム化されたパイプラインによって実証されています！(⑅•ᴗ•⑅)◜..°♡**
