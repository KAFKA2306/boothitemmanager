# 🌸 パイプライン手順と技術メトリクス仕様だょ！ 🌸

データの取得からダッシュボードの構築までの流れと、厳しい品質テストのメトリクスについてまとめたよぉ！(⑅•ᴗ•⑅)◜..°♡

## 🎀 1. パイプラインの6ステップ
1. **Crawler**: BOOTHのHTMLをクローリングして `data/raw/index.ndjson` に蓄積するよ。
2. **Normalizer**: HTMLから不要な情報を削り、オントロジー（`ontology/`）に基づいてタグを正規化！
3. **DB Builder**: 構造化したデータを `data/structured/catalog.json` に出力。
4. **Graph Builder**: アイテム間の共起関係を計算して `api/tag_graph.json` をつくるの🍭
5. **Search Builder**: 静的検索用の `api/search_index.json` や分割シャードを生成。
6. **Auditor**: 自動監査スクリプト `scripts/audit_pipeline.py` で整合性を確認！

---

## 🐾 2. 厳格な自動監査チェックリスト (Audit Checklist)
パイプライン完了後に実行され、1つでも **FAIL** があると即 **REJECT** されるよ！

- **スキーマ監査**: 必須フィールドの存在、型一致、IDの一意性をチェック。
- **データ整合性**: 重複レコードや参照切れ（孤立データ）がないこと。
- **実行フロー**: 中間データの欠落がなく、決定性（同じ入力➔同じ出力）が保たれていること。
- **グラフ監査**: 不正なエッジや孤立ノードがなく、循環参照がないこと。
- **検索再現性**: `search_index.json` と実データが完全に一致し、ソート順が正しいこと。
- **ログ監査**: トレースIDが途切れず、不正な改ざんがないこと。

## ⚡ 3. 技術評価メトリクス (Performance & Quality Targets)
システムの軽快さと正確性を保証するための測定ターゲットだよっ☆

### ① 検索・ロード性能 ($N = 10,000$ 件)
| 評価項目 | 測定シナリオ | 許容値 (p50) | 限界値 (p99) |
| :--- | :--- | :--- | :--- |
| **単一キー検索** | インデックス検索 | $\le 1.0\text{ ms}$ | $\le 5.0\text{ ms}$ |
| **複数条件フィルタ**| カテゴリ + タグ | $\le 2.0\text{ ms}$ | $\le 8.0\text{ ms}$ |
| **あいまい検索** | 類似度・テキスト検索 | $\le 5.0\text{ ms}$ | $\le 20.0\text{ ms}$ |
| **キャッシュロード**| `likes_cache.json` 読込 | $\le 10.0\text{ ms}$ | $\le 30.0\text{ ms}$ |

### ② インデックス更新・マージ性能
- **差分マージ時間 ($M=100$ 件)**: $\le 50\text{ ms}$ (目標) / $\le 100\text{ ms}$ (限界)
- **ピーク時RAMオーバーヘッド**: 既存インデックスの **1.5倍以内**
- **アトミック書き込み安全性**: テンポラリ書出 + `os.replace` によるアトミック置換でデータ破損率 **0.0%**

### ③ ノーマライザ変換精度
- **カテゴリ分類・アバター判定精度**: **F1-Score $\ge 0.98$** (誤分類は即REJECT！)
- **PIIマスキング漏れ率**: **0件** (個人情報の漏洩を完全防止)
- **HTML構造変化への耐性**: BOOTHのレイアウト変更時のパース成功率 **$\ge 95\%$**
